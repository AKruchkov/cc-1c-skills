# /v8-xsd-fetch — XSD-схемы платформы

Скачивает XSD-схемы формата выгрузки из репозитория
[yellow-hammer/namespace-forest](https://github.com/yellow-hammer/namespace-forest)
и раскладывает по версиям формата: `.v8-xsd/<версия>/*.xsd`. По этим схемам навыки
проверяют выгрузку без базы; нет схем — нет проверки.

## Команда

```powershell
powershell.exe -NoProfile -File "${CLAUDE_SKILL_DIR}/scripts/v8-xsd-fetch.ps1" [-Versions "2.20,2.21"] [-List]
```

| Параметр | Описание |
|----------|----------|
| `-Versions "<список>"` | Версии формата через запятую. Без него — все доступные (около 600 КБ на версию) |
| `-List` | Показать доступные версии и какие уже есть локально, ничего не скачивая |
| `-OutPath <путь>` | Каталог схем, если нужен не тот, что в проекте |
| `-Force` | Перекачать файлы, которые уже есть |
| `-Ref <ветка/коммит>` | Состояние репозитория-источника, по умолчанию `main` |

## Куда кладёт

`-OutPath` → `xsdPath` из `.v8-project.json` (относительно файла) → `.v8-xsd` рядом с
`.v8-project.json` → `.v8-xsd` в текущем каталоге.

Рядом со схемами — `README.md` (что это и откуда) и `source.json` (репозиторий, коммит, дата).
Схемы — собственность ООО «1С-Софт»: каталог в Git не добавлять, его место в `.gitignore`.

## Какую версию брать

Версия формата — атрибут `version` корня `Configuration.xml` выгрузки (например, `2.20`),
а не номер релиза платформы. Достаточно версий тех выгрузок, с которыми работает проект.

Без сети: скопировать каталоги `schemas/designer/<версия>/` из репозитория-источника вручную.
